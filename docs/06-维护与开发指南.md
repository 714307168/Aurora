# 06 · 维护与开发指南

面向接手者：怎么改、往哪改、有什么坑。**先读 01、02**，熟悉结构与设计系统。

## 1. 常规操作

### 换主色
只改 `assets/aurora.css` 顶部 `:root`：
```css
--aurora:#22d3ee;   /* 主色 */
--aurora2:#3b82f6;  /* 辅色 */
```
改完**递增版本号**（见 §2）。

### 加侧栏模块
在 `sidebar.php` 复制一个 `.side-box` 块，用 Typecho 内置 Widget 取数据。常用 Widget：
- `Widget_Metas_Category_List` 分类
- `Widget_Contents_Post_Recent` 最新文章
- `Widget_Metas_Tag_Cloud` 标签云
- `Widget_Contents_Post_Date` 归档
- 自定义热门：`typecho_contents` 按 `commentsNum DESC` 查询（见 `sidebar.php` 现有实现）

### 改导航
`header.php` 的 `.aurora-nav`：首页 + `Widget_Contents_Page_List`（页面）+ `Widget_Metas_Category_List`（分类下拉）。改页面/分类入口就在这两个 Widget。

### 换 logo / favicon
替换 `assets/logo.svg`；`header.php` 里 favicon 引用同一文件。

### 改正文排版
`.post-body` 相关规则在 `aurora.css`（字号/行高/标题色条/代码块/表格/引用）。

## 2. ⚠️ 版本号（最容易踩的坑）

`aurora.css` 和 `aurora.js` 被 **CDN / 浏览器缓存**（`max-age=2592000` 一个月）。改了这两个文件**必须递增引用处的 `?v=`**：

- `header.php`：`aurora.css?v=20260830` → 改成新日期，如 `?v=20260831`
- `footer.php`：`aurora.js?v=20260829` → 同步递增

否则线上看到的永远是旧版——这曾导致 TOC/代码增强「改了不生效」的假象。

## 3. 常见坑汇总

| 坑 | 现象 | 解决 |
| --- | --- | --- |
| CDN 缓存 JS/CSS | 改了不生效 | 递增 `?v=` 版本号 |
| highlight.js 用错版本 | 控制台 `require is not defined` | 用 `cdnjs` 的 `highlight.min.js`（浏览器版），**别用** npm 包 `lib/common.min.js`（Node 版） |
| 友链页白卡片突兀 | 深色主题下卡片发白 | `.aurora-links` 用 `var(--card-bg)` 玻璃卡片 |
| 主题类缺方法 500 | 文章页 500 | `functions.php` 的 `Aurora` 类必须定义模板里调用的 `Aurora::xxx()`；模板调用前先确认方法存在 |
| pageNav class 名 | 分页样式失效 | 分页容器是 `.page-navigator`（Typecho pageNav 输出） |
| 备案号混入开源 | 版本泄露个人备案 | 备案走 `aurora_beian` option，主题不硬编码 |
| 响应式两栏 | 900px 附近侧栏掉下方 | 断点在 `aurora.css` 尾部 `@media(max-width:768px)`；低于即折叠 |
| 评论区 | 显示「评论已关闭」 | 全站 allowComment=0；行为在 `comments.php` |
| TOC 不显示 | 章节不足 | `buildToc()` 需 `.post-body` 内 ≥2 个 `h1/h2/h3` |

## 4. 发版流程（本地 → GitHub → 线上站）

```bash
cd /root/aurora-theme
# 0. 修改主题代码后，先同步更新 docs/ 对应文档（见 §6 文档同步规则）
git add -A
git commit -m "描述变更（含文档同步）"
# 2. 推 GitHub（SSH）
GIT_SSH_COMMAND="ssh -i ~/.ssh/aurora_github -o IdentitiesOnly=yes" git push
# 3. 同步到线上站（仓库与线上 usr/themes/Aurora 对应）
for f in *.php style.css assets/*; do cp "$f" /home/wwwroot/www.liuyg.cn/usr/themes/Aurora/"$f"; done
chown -R www:www /home/wwwroot/www.liuyg.cn/usr/themes/Aurora
# 4. 若改了 css/js，bump 线上 header/footer 的 ?v=
```

> 线上站 `usr/themes/Aurora` 与本仓库保持同步；线上站特有的（备案号 `aurora_beian`）走数据库 option，不在代码里。

## 5. 验证要点（改完必查）

- 首页 `curl -sI` 200
- 文章页 200（不 500）
- 若改 css/js：`curl -s https://www.liuyg.cn/usr/themes/Aurora/assets/aurora.js?v=最新` 确认新内容（或看 view-source 版本号）
- 友链页、归档页、404 正常
- 页脚备案显示（读 option）

## 6. 文档同步规则（强制）

**改代码 = 改文档**。每次对主题做任何变更，必须同一次提交里同步更新 `docs/`，并在 commit message 标注。具体对应：

| 变更 | 要更新的文档 |
| --- | --- |
| 模板 / 文件结构 / 运行机制 | `01`、`03` |
| CSS / 组件 / 断点 | `02` |
| JS 功能 / TOC / 代码增强 | `04` |
| 主题设置 / option | `05` |
| 新增坑 / 操作流程变化 | `06`（常见坑表、发版流程） |
| 核心概念变化 | `07` |
| 新增/改名文档 | `README.md`（索引表） |

判断是否要更新文档的简单准则：**这次改动会不会让「照着文档操作的人」得出错误结果？** 会 → 必须更新。
